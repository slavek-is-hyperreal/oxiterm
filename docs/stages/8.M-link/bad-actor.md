## Findings (as confirmed; tests named)
BL01 medium ROBUSTNESS: the cycle collector allocates its own work vectors, so collecting garbage that fits in memory can itself trap out_of_memory (poisons the instance). 120k garbage 2-cycles (106/256 pages used) -> collect_cycles OOM; 100k works but grows 92 -> 248 pages (~2.7x). Since 8.M-link `deinit` always runs the collector, `deinit` can now trap OOM where it used to return a count. Test lower/bad_actor_link.rs `collect_cycles_needs_headroom_probe` (fails), `many_small_cycles_in_a_loop_are_collected` (fails: main fits, deinit OOM).
BL02 low DESIGN: garbage cycles created inside one host call are never collected (trial deletion only from host `collect_cycles`) and the OOM path does not try a collect before trapping; 2M 2-cycles in one call -> out_of_memory at the default 16 MiB although every object is garbage. Same as Stub (no regression), but now a collector exists. Test `cycles_without_a_host_collect_hit_the_memory_limit` (documents).
BL03 low HOST-MISUSE: `oxi_rt_init` is now an exported ABI function. Called on a fresh linked module with heap_base 0 ("keeps the default"), the runtime's own `__heap_base`, or an address inside program static data, the allocator starts INSIDE the program's static data (typedescs, literals): first allocation overlaps and static data is corrupted. Validation only checks `>= runtime __heap_base`. Called after `oxi_init` it is harmless. Test wasm/bad_actor_link_merge.rs `rt_init_recall_matrix` (fails).
BL04 low PRIVACY/REPRODUCIBILITY: the embedded runtime carries panic-location strings with the builder's absolute cargo registry path (`/home/<user>/.cargo/registry/src/index.crates.io-.../dlmalloc-0.2.14/src/dlmalloc.rs`) and the rustc commit hash, so EVERY compiled .wasm (also from the browser playground and every `oxi build`) embeds the builder's home dir and the artifact is not byte-identical across machines/CARGO_HOME. Check: `grep -a -o '/home[^"]*' $TMPDIR/hello_linked.wasm`.
BL05 info BUILD: build.rs `rerun-if-changed` lists the 6 files that make up the wasm build TODAY (complete), but a new src file, Cargo.lock (dlmalloc bump), rust-toolchain.toml or RUSTFLAGS env change would not rebuild the embedded runtime; nested cargo gets no --locked/--offline/--frozen; `../oxiscript-rc` path + nested cargo means the crate cannot be built from a published tarball (no publish settings exist today). Verified: two clean builds of oxiscript-rc with the build.rs RUSTFLAGS into different target dirs are byte-identical and identical to the embedded artifact (same machine/toolchain/CARGO_HOME).
BL06 medium PERF (DEMONSTRATED: `work(1000)` passes in Stub and traps OutOfFuel in Linked under default Limits, test `default_fuel_budget_regression`): fuel per operation is 6.5-10.5x higher than Stub (new class: 398 -> 3070 fuel/iter; array literal 579 -> 5584; struct in array 829 -> 8727; template `${i}` 1657 -> 12006). The default budget (10M fuel/call) therefore allows ~3k allocations per call instead of ~25k: a program that ran in Stub can now trap OutOfFuel (workload `work(1000)` = 33M fuel Linked vs 4.2M Stub). Wall time 2.5-2.7x. Numbers in perf section. Tests lower/bad_actor_link_perf.rs.
BL07 low SIZE/LOAD: Linked module 58-60 KB vs 3.5-5 KB (12-16x); compile 3.4-4.5 ms vs 0.7-2.2 ms (merge re-parses and re-encodes the whole runtime on each compile); instantiate 3.5 ms vs 0.4 ms (8-10x).
BL08 medium (latent contract gap, owner 8.R host) LIVENESS: nothing in oxiscript-runtime ever calls `oxi_collect_cycles` (pump, call_export, tick: grep finds only `deinit` and tests), so a long-running instance leaks every garbage cycle until the memory limit: `@host export mk()` creating one 2-cycle per call dies with out_of_memory after exactly 262144 calls (16 MiB). ABI says "the host calls collect between events". The `oxi_gc_step` bounded form is stripped from linked modules, so a host has only the unbounded call. The new `deinit` collect hides all of this from the leak checks (un-ignored L04 tests pass only because of it). Test lower/bad_actor_link.rs `long_running_instance_leaks_cycles_until_oom_without_host_collect` (fails).

## Held up (tests pass)
Merger: no oxi:rt import / no `__oxi_set_trap`, `oxi_gc_*`, `__heap_base` export; runtime data below `__heap_base`, program data above, no overlap, table/elements in bounds, for 1 literal, 5000 literals (505 KB), 100 KB and 1 MB literals, 600 struct types, mixed (wasm/bad_actor_link_merge.rs `stress_layouts_merge_and_run`); literals and static data intact after 3000-block churn; no leak. Function count 9800 fits in both modes (limit shared with Stub). Differential Stub vs Linked: 65 corpus/doc/example programs + every no-capability export called with 0/1/7 -> identical logs/results/trap kinds (`stub_and_linked_agree_on_corpus`; the only leak is 02_drag.oxs live=3 in both modes = host-held callbacks); seeded generator 5000..5300 and 6000..8000 x 12 funcs x plain+meta (24k+3.6k functions, each in Stub and Linked, vs the reference model): 0 Linked-only failures (10 + 2 generator artefacts fail identically in both: log line > 64 KiB, i32 overflow, OOM). Compiler traps (bounds, overflow, div0, stack overflow, bad_utf8, slice bounds) same kind Stub/Linked. Runtime traps OOM/BadUtf8/Bounds arrive through oxi_trap_kind exactly once; memory limit sweep 1..39 pages: only success or OOM (or load rejection). OOM then restart recovers. `array.new` of 2^28..2^31 elements of 1/4/8 bytes: OOM or Bounds, never a wrapped size. 10^6 random f64 bit patterns + 200k ordinary + 600 edge values: 0 mismatches vs the documented format, all round-trip, deterministic across instances. deinit collector does NOT hide true leaks (acyclic, cyclic-typed, cycle member with extra retain all stay counted; real cycle freed). Double deinit harmless; calls after deinit give NullDeref (no UAF). Reload 300x: memory and instance counts flat. 100k ring and 200k-deep structures collect/free without stack overflow. 4096-byte scratch payloads x200: runtime state intact. 1 MB alloc/free churn x300: memory flat (1 MiB growth once). Guest cannot declare an `oxi:rt` import (IDL requires `host:`), oxi_set_trap is not exported. `oxi build`/`oxi run` hello.oxs OK, CLI output byte-identical to the library. `cargo build -p oxiscript-playground --target wasm32-unknown-unknown` green (cached; the wasm32 artifact itself was not executed: no wasm-bindgen glue here).
