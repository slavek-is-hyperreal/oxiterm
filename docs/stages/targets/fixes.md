## Mutation check of the engine layer (F1a/F1d)
`runtime.rs::engine_config_tests::engine_refuses_every_proposal_outside_the_target` builds `Engine::new(&host.config)` for each target and requires `Module::new` to refuse SIMD, relaxed-SIMD, memory64, table64, two memories, shared+atomics, externref, trunc_sat and GC; `engine_follows_max_target_for_tail_call` proves it reaches the real config (`return_call` refused on Device, accepted on Web). Flipping `.wasm_simd(false)` to `true`: RED ("engine for max_target device accepted simd"). Flipping `.wasm_memory64(false)` to `true`: RED ("accepted memory64"). Flipping `.wasm_relaxed_simd(false)`: stays green (relaxed-SIMD cannot validate without SIMD, which is off; the setter is belt and braces). All three restored.

Note: since the runtime now always compiles wasmi `simd`/`memory64`, the `--features wasmi/simd,wasmi/memory64` and `-p oxiscript-runtime -p oxiscript-rc` runs build the same features as the per-package run; they no longer exercise a different configuration. The engine-layer test above is what proves F1a.
