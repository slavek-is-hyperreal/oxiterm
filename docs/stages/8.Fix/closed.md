## Open Questions for the Owner

1. **Non-constant `case` labels in `Int`/`Str`/`Nullable` switches (`[R3-53, R2-106]`)**: `oxiscript-syntax/tests/corpus/valid/11_switch_expr.oxs:7` intentionally uses a runtime expression `case ("a" === n ? "x" : "y"): 2` in a string switch (TypeScript-compatible; lowered sequentially). Should `Int`/`Str`/`Nullable` switches keep allowing runtime case expressions (with `Union`/`Enum`/`Bool` requiring constants), or should non-constant case labels be rejected everywhere and `11_switch_expr.oxs` updated?
2. **Capturing `this` in a closure inside a `mutating` struct method (`[R3-53, R2-106]`)**: `oxiscript-lower/tests/programs_hard.rs::p43_closures_capturing_this` explicitly pins that reading `this` in a closure inside a `mutating` struct method is valid and captures a value snapshot (`snap()` sees `10`, caller's later mutation sees `100`), while mutating `this` inside the closure is rejected. Confirm keeping this documented value-snapshot semantics vs forbidding `this` capture there and changing `p43_closures_capturing_this`.
3. **`Q-LANG-3` (`readonly`, `private`, `static` on struct value copies, `[R3-210]`)**: Current checker behavior (now pinned by test) keeps `readonly` fields non-assignable on copies (`OXS-E0109`), `private` fields inaccessible outside methods (`OXS-E0119`), and `static` fields type-level only (`OXS-E0108`). Confirm this is the final v1 rule.
4. **120k-node drop fuel (`[R2-115]`)**: After `gemini-rtlink` (`8.M-link`) merges and establishes the Linked fuel baseline (BL06), should dropping large graphs stay bounded by `fuel_per_call` (caller raises fuel or drops incrementally) or gain a bounded deferred-drop step in `oxiscript-rc`?
5. **Post-`gemini-rtlink` `oxiscript-wasm` leftovers (`[R3-32, R2-108, R2-113, R4-17]`)**: Wasm local reuse (liveness free list) and `bad_cast` tag-check elision were intentionally deferred to avoid merge conflicts with `gemini-rtlink`; schedule them immediately after `8.M-link` merges (and before `8.3a`).
