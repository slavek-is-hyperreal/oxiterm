# BAD ACTOR Round 2026-11-27-1 Fixes (main-side code)

(The crate `oxiscript-bench` was renamed `oxiscript-perf` on main before this merge; paths below use the new name.)

Fixes for the main-side findings specified in [`docs/stages/rounds/2026-11-27-1.md`](2026-11-27-1.md) on branch `ba-round1`. No BAD ACTOR test was weakened, deleted, or `#[ignore]`d.

## Findings fixed

### R1-40 (MEDIUM, OxiPerf): strict `u32` checksum validation and agreement
- **Files changed:**
  - `oxiscript/oxiscript-perf/src/workloads.rs`: added `parse_u32_checksum` (accepts only exact non-negative JSON integers within `0..=u32::MAX`; rejects missing, `null`, negative, fractional, string, boolean, and `> u32::MAX` values), `ChecksumEntry`, and `verify_run_checksums` (delegates agreement verification to `verify_checksums` after confirming every run contributed a valid `u32` checksum). Added unit tests covering all malformed shapes.
  - `oxiscript/oxiscript-perf/src/driver.rs`: validated child JSON is an object in `spawn`; validated every run's `checksum` via `parse_u32_checksum` alongside `checksum_stable` and `fuel_stable`, recording missing/malformed/unstable/spawn-failed runs as `valid: false` with a descriptive `invalid_reason` and feeding every run into `verify_run_checksums` so any invalid run fails the workload digest and makes `oxiperf run` exit non-zero.
  - `oxiscript/oxiscript-perf/src/report.rs`: independently re-validates every `raw.jsonl` record's `u32` checksum, stability flags, and per-workload agreement inside `analyze`; excludes invalid runs from `rows`, forces `digest_ok` / `digests_ok` to `false`, suppresses `ratio_vs_rust_native` (and therefore verdicts and geomeans) for any workload whose digest is not `true`, and renders `-` (not `baseline`) for non-baseline rows without a ratio. Added unit test `analyze_rejects_malformed_or_missing_checksums_even_if_marked_valid`.
  - `docs/bench/oxiperf.md`: documented the strict `u32` checksum validation, failure semantics (`digests_ok: false`, suppressed verdicts/geomeans, non-zero exit), and re-verification in `analyze`.
- **Verification:** `cargo test -p oxiscript-perf --no-fail-fast` (24 unit + 2 `bad_actor_round1` including `r1_40_non_u64_checksum_skips_verification` and `probe_wrong_positive_checksum_is_caught` + 2 `smoke` — all pass) and `cargo clippy -p oxiscript-perf --all-targets -- -D warnings` (clean).

### R1-50 & R1-51 (LOW, `scripts/oxiscript-version.sh`): strict tag parsing and decimal `carry=N`
- **File changed:** `scripts/oxiscript-version.sh`
  - **R1-50:** validates `$TAG` against the strict ASCII decimal regex `^oxiscript-v([0123456789]+)\.([0123456789]+)\.([0123456789]+)$` before any arithmetic or git diff; any tag with a suffix or non-decimal component (e.g. `oxiscript-v0.0.2-BUMP`) prints an error to stderr and exits `1`. Extracts `X`, `Y`, `C` from `BASH_REMATCH[1..3]` with explicit base-10 `$((10#...))`.
  - **R1-51:** extracts `carry=N` using `[0123456789]+`, validates it as ASCII digits, and parses `CARRY=$((10#$CARRY_RAW))` (and `DIFF=$((10#$DIFF))`) so leading zeros are always decimal (`carry=0100` -> `100`, giving `101 + 100 = 201`; `carry=08` -> `8`, no octal error).
- **Verification note:** `bash`, `git`, and `node` execution are disallowed/restricted in this environment (`bash` was denied by supervisor policy; `git`/`node` are disallowed by task constraints). Verified line-by-line against `scripts/test/bad_actor_round1_version.mjs`; the lead should run `bash -n scripts/oxiscript-version.sh`, `scripts/oxiscript-version.sh --check`, and `node --test scripts/test/bad_actor_round1_version.mjs`.

### R1-30 (LOW, `std/collections`): detect re-entrant mutation during `hash()` / `equals()`
- **Files changed:**
  - `oxiscript/std/collections.oxs`: added a wrapping `u64` modification counter (`modCount`) to both `Map<K, V>` and `Set<T>`, incremented on every mutation (`set`, `add`, `remove`, `clear`, `rehash`). Captured `modCount` before every user `hash()` and `equals()` call (`has`, `get`, `getOr`, `set`, `add`, `remove`, `findBucket`) and checked it immediately afterwards; on re-entrant mutation, traps deterministically (`bounds` via out-of-bounds bucket index). `forEach` behavior is preserved.
  - `docs/oxiscript/std.md`: documented the re-entrant mutation rule and deterministic `bounds` trap for `Map` and `Set`.
  - `oxiscript/oxiscript-lower/tests/std_collections.rs`: added `reentrant_mutation_in_hash_or_equals_traps_deterministically` covering re-entrant `Map` `hash()` and `Set` `equals()`.
- **Verification:** `r1_30_map_reentrant_equals_keeps_map_consistent`, `reentrant_mutation_in_hash_or_equals_traps_deterministically`, and all existing `std_collections` / `bad_actor_8std` tests pass.

### R1-31 (LOW, `std/string` `parseFloat`): reduce per-digit fuel cost and document limits
- **Files changed:**
  - `oxiscript/std/string.oxs`:
    - Rewrote `parseFloat`'s mantissa scanner as tight, single-variable phase loops using wrapping byte/index arithmetic (`+%`, `-%`), eliminating per-digit nested branch joins and overflow checks.
    - Stripped exact trailing decimal zeros from `mant` before the fast paths so inputs such as `1000...e-n` hit the Clinger fast path instead of falling back to `BigUint`.
    - Passed `firstSigPos` and `dotPos` to `parseFloatBigInt` so the 768-digit `BigUint` fallback starts directly at the first non-zero digit, accounts for remaining integer digits in $O(1)$, and terminates its sticky-bit scan on the first non-zero digit past 768.
    - Rewrote `repeat` using exponentiation-by-squaring string concatenation (`O(log count)` steps instead of `O(count)` byte pushes).
  - `docs/oxiscript/std.md`: documented `parseFloat`'s 768-digit + sticky-bit cap, measured per-digit and fixed fuel costs, and practical maximum input lengths under the default 10M fuel budget.
- **Measured fuel (release, `r1_31_parse_float_long_input_exhausts_fuel`, default 10M fuel budget):**
  - `kind 0` (`0.000...1e20001`, 20,000 digits): ~64 fuel/digit, total **1,298,050** fuel (was OutOfFuel at ~1,075/digit).
  - `kind 1` (`1000...e-20000`, 20,000 digits): ~105 fuel/digit, total **2,136,562** fuel (was OutOfFuel at ~1,645/digit + BigUint).
  - `kind 2` (`0.111...1`, 20,000 digits, BigUint path): ~1.88M fixed + ~53 fuel/digit, total **2,945,486** fuel (was OutOfFuel at ~1,617/digit + BigUint).
  - `kind 3` (`999...9.5`, 20,000 digits, overflow): ~53 fuel/digit, total **1,092,292** fuel (was OutOfFuel at ~1,056/digit).
- **Verification:** `r1_31_parse_float_long_input_exhausts_fuel` (release) and `bs01_parse_float_differential_200k` (release, 200,000 differential inputs against Rust `f64::from_str`) pass bit-exact.
